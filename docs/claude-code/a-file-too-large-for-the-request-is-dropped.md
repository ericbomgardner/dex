# A file too large for the request is dropped (CLI v2.1.312, SDK 0.3.312)

Probe: `Sidecar/test/media-dropped-probe.ts`, an opus session reading a 19.97MB one-page PDF of noise whole, then the transcript.

Before each request the CLI counts every image and document in the conversation. Once the documents are over 24MiB (base64, so about 18.9MB of PDF), it takes the oldest out until they're under 14MiB, and puts `[media removed: request limit]` in their place. It tells nobody. The only report is a telemetry event, `tengu_media_byte_cap_stripped`. Values read from the CLI's source, not measured one by one: 24MiB for documents and 24MiB for all media on first-party, 75MB for all media elsewhere, 10MiB taken off below the cap when stripping. The probe pins one point either side: 17.9MB was sent whole and seen, 19.97MB was dropped.

- **Only the request record shows it.** The `user` turn keeps the `document` block it was read with. The `api-request-blob` written for that request (see [A transcript records each request](a-transcript-records-each-request.md)) has the same `tool_result` under the same `tool_use_id`, with the placeholder text where the document was. `TranscriptDocument` and `transcript-render.py` read the blob for that and set `wasDropped` / `was_dropped` on the call, but only when the placeholder is a line of its own and the blob comes before the next `api-request` record after the result. The oldest file goes first, so a file the model read and answered from can be stripped from a later request, and that one was seen. The row then says "too large to send, never seen" in red, and so does a collapsed run's sentence.
- **The model is told only by the placeholder,** and a chat once went on to describe a lease it never got. Every session, chats included, has `MEDIA_BRIEF` on its system prompt, which says the placeholder means the file never arrived.
- **`Read` sends a PDF whole only on models it lists as taking one.** On haiku the same file went to page rendering, which needs `pdftoppm`; Dex doesn't ship it. So the probe runs on opus.
- **A big PDF is read a few pages at a time.** `Read` with `pages` renders those pages to JPEG with `pdftoppm`, found on the host's PATH, which carries `/opt/homebrew/bin`; with Homebrew's poppler installed, haiku read pages 60-65 of a 100-page PDF and quoted page 63. Without it the call fails, saying to install poppler. Rendered pages are images, and count toward the same cap.

Code: `TranscriptDocument.dropped`, `ToolCall.wasDropped`, `RunSentence`, `NativeRows.call`, `MEDIA_BRIEF` (`briefs.ts`, `chat.ts`). Tests: `TranscriptDocumentTests.testAFileTheRequestDroppedIsMarkedOnItsCall`, `transcript-render-test.py`.
