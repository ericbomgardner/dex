# A message can take the turn back from a foreground task (CLI v2.1.283, SDK 0.3.283)

Probe: `Sidecar/test/background-foreground-task-probe.ts` — a foreground agent and a foreground Bash, each with a message sent in mid-run, against a control that backgrounds nothing.

A foreground agent or a foreground Bash holds the turn for as long as it runs. A message sent into that stretch is written but never read: there is no step left in the turn for the model to read it in (40s against a trivial agent, minutes against a real one). `interrupt` would unblock it, but ends the turn and takes the agent with it.

`query.backgroundTasks()` is the SDK's own Ctrl+B: every in-flight foreground task moves to the background, each blocking call returns at once, the turn carries on, and the task keeps running. The same message is then answered in seconds with the agent still going. The host does it on every `send` (`HostedSession.send`), so there is no button.

**Once isn't enough.** A foreground Bash is announced as a task about 3.5s after it starts (3.6–4.7s measured), and `backgroundTasks()` before that answers `true` and moves nothing. A message sent while the model was still writing the call, or in the command's first seconds, then sat behind the whole command: 14–60s behind builds, test runs and network calls in real sessions. So while a sent message hasn't been taken (`#messageWaiting`, cleared by `command_lifecycle` or the turn's result), the host asks again on every `task_started`. The move then lands about a second after the announcement. Probe: `Sidecar/test/now-priority-probe.ts`, the host run, sent 1s into a 20s command.

**The gate is `state === "running"`, not the task set.** The task set says something is out there; it does not say the turn has no step left to read a message in, and a turn can be blocked with no task at all — a short shell command, a `Read`, a `WebFetch`, the model mid-step. Asked of a session that is only thinking it backgrounds nothing and costs a round trip, which is the price of never missing one. Not `asking`: a parked session cannot be unblocked by a message whatever is done to its tasks. (Whether a foreground Bash announces a task depends on how long it runs — `echo hi` announces none, 75s of shell does — so a task-set gate would not even be reliable on the case it looks built for.)

**The backgrounded call comes back as the ordinary async launch receipt**: `status: "async_launched"` with `agentId` beside it, the same shape a `run_in_background: true` agent produces. `TranscriptRecord.isLaunch` refuses to read a receipt as an answer, so the call stays pending, the id is noted so the agent's transcript opens, and the later `<task-notification>` settles it with the CLI's counts. Read as a result instead, a four-minute agent would appear to finish the instant you typed at it. A backgrounded **Bash** comes back as `Command was manually backgrounded by user with ID: …` with the output file beside it, so its call really does settle; `session.tasks` keeps the row honest, as [A background shell command is a task too](a-background-shell-command-is-a-task-too.md) describes.

**Shrugged off rather than refused**, the opposite of `stopTask`: this runs on the way to delivering a message that is already away, and every failure — an SDK without the call, a session started with `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS`, which throws — is one the message survives. Since the host sends with `priority: "now"`, the order is load-bearing and reversed: the message waits for `backgroundTasks()` to answer, because `"now"` kills a foreground agent that is still in the foreground (see [A message can cut in](a-message-can-cut-in.md)).

Probe caveats: the control run must be asserted, not printed — without a run that backgrounds nothing, an agent that was about to finish anyway reads as a successful unblock. And the session must be held open for the *task*, not the turn: backgrounding is exactly what lets the turn end while the task runs on, so a run closed a beat after the result reads the settle as missing.

Code: `HostedSession.send`, `HostedSession.#cutIn`, `HostedSession.#unblock`, `HostedSession.backgroundTasks`, `TranscriptRecord.isLaunch`, `session.tasks`.
