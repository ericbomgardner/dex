# A session that drives the screen (CLI v2.1.316, SDK 0.3.316)

Probe: `Sidecar/test/screen-takeover-probe.ts` — one session in auto mode running a plain, a marked-and-allowed and a marked-and-denied command, and a second running one plain and one marked `Monitor`.

Sessions verify UI by posting clicks to the HID tap and `activate`-ing windows while the user is at the keyboard, and in `auto` a Bash call never reaches `canUseTool`, so the app cannot tell that command from `ls` on its own.

**The door.** The host installs a PreToolUse hook on Bash through `query()`'s `hooks` option — a callback in the host process, not a subprocess — and answers `permissionDecision: "ask"` for a command that drives the screen. **A hook's `ask` goes through `canUseTool` in auto mode**: the marked command reaches the callback, the plain one doesn't, an allow runs it, and a deny's `message` reaches the model as the tool result. Without that there is no mechanism. `#park` files the ask as `kind: "takeover"` with options `allow_once`, `redirect`, `reject_once`; `redirect` is a deny whose message is the host's words (`REDIRECT_MESSAGE`), so a refusal from the card and one the app makes on its own read the same to the model.

**A Monitor is a shell to the hook** (the 2.1.314 changelog: "Bash hooks now run on Monitor's shell commands"). A `Monitor` call's command reaches the Bash PreToolUse hook with `tool_name: "Bash"`, so the same matcher catches it; the plain one goes no further, and a marked one's `ask` reaches `canUseTool` labelled `Monitor`, not `Bash`. `screenDrive` reads both names, or a marked watch gets a plain "Use Monitor" card instead of the takeover.

**What decides is in the app, not the host**, because only the app can read idle time. `ScreenTakeoverPolicy.decide` allows when pointer and keyboard have been still for `idleAfter` (30s, off `CGEventSource` via `InputIdle`) or when the same session already has the screen this turn (one ask per click is six cards per verification); otherwise the ask stands for the card. `HostSessions.answer` fires `onTakeoverAllowed` either way, `SessionStore.screenTakeovers` holds the grant, `ScreenTakeoverBar` draws it red across the window with a Stop that interrupts, and one notification goes out per turn (`SessionTransitions.takeoverDraft`), retracted with the grant — `withdrawOvertakenNotifications` unions the takeover keys into the standing set, or the next rebuild takes it back.

**When the grant ends.**
- On a `session.status` the policy **lists** (`idle`, `done`, `failed`), not "anything but running" — a state the host adds should leave the bar up, since the bar is the only thing saying the session has the machine. `idle` counts only once the drive's own call is no longer a task: a Monitor or a backgrounded Bash outlives its turn's result ([a watcher is a task](a-watcher-is-a-task-the-cli-cannot-tell-from-a-shell.md)), so the bar waits for the lapse below, and Stop ends that task as well as the turn.
- Mid-turn, 60s after the newest drive's own result is written (`ScreenTakeoverPolicy.hasLapsed`, `DriveReturns`), found in the transcript by its command among Bash and Monitor calls since the ask names no call — unless the host still lists that call as a task, as it does a backgrounded Bash or a Monitor still watching.
- On `hostChanged`, for any key the host no longer holds: a host replaced mid-turn clears the index with no per-session word, so the bar would otherwise stand for the life of the app.

**Detection is a contract first and a net second.** Every session, whatever model and brief, is told to prefix global input with `DEX_DRIVES_SCREEN=1` (`SCREEN_BRIEF`, appended to the `claude_code` preset with `FOLDERS_BRIEF`); `drivesScreen` reads that mark. The regex beside it (`SCREEN_HABITS`: `cliclick`, `keystroke` followed by a string or `return`/`tab`/`space`, `key code` followed by a number, `cghidEventTap`/`SessionEventTap`, `to activate`, and `click`/`drag`/`scroll` followed by a number) catches the shapes seen before the mark existed. Five shapes there look over-tight and aren't: what follows `keystroke`, because commit messages and comments in any app that takes text say "keystroke" all the time; `to activate` rather than `\bactivate\b`, because `source venv/bin/activate`; the number after `click`/`drag`, because `mv drag-handle.svg`; and no `-`, `.`, `/` or letter before the word and no `>` after the number, because `git merge goal-drag 2>&1`; the tap's name rather than `CGEvent`, because `CGEvent.postToPid` is the route the brief and `REDIRECT_MESSAGE` send sessions to, and the net put the bar up for every helper written that way. A session that names its tool something new slips past unless it follows the brief and marks the command.

With no app connected the ask parks like any other — the price of the decision living where the idle time is.
